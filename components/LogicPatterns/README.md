# LogicPatterns

What a3t's flows can do, drawn: a flow after a try, a long flow wrapped into rows, an action as the way in, a flow that waits, and steps all at once with the first of several waits. A showcase card, proposed.

- After a try, the path the flow took is green, a loop says how often it ran, and what the flow didn't use fades.
- A long flow wraps into rows where it saves, so each row is one stretch of work, and an arrow carries it on.
- An action is how people and agents come in. A bracket marks what it works out first, which its preview and its review card show. Then it saves, and a second bracket marks what runs after it saves, in the same transaction.
- A flow that waits is built as any other. A person's task has a way on for each outcome, a wait is a ring, and a bar marks each point where the flow saves. Who acts is at each step's foot, reminders and the deadline hang below the task in the order they come, and live, each step says how many cases wait there. A flow that waits can start by itself on a record: as it is created, on a date of it, or when a condition comes to hold. A flow that needs no input can run on a schedule.
- All at once: the flow goes on when its rows are done, or when enough of them are. The first of: whichever wait comes first takes its way.
